# 拾年 / CHRONA 核心业务流程

本文档以当前 Flutter 代码为事实来源，整理已经实现的业务链路。数据库字段以 [`docs/database-schema/`](./database-schema/) 为准。

## 代码模块关系

```text
TodayScreen
├─ TaskProvider ───────────── AppDatabase.task
├─ FocusProvider ──────────── NotificationService
│   └─ FocusNoteScreen
│       └─ FocusSessionProvider ── AppDatabase.focus_session
└─ JournalProvider ────────── AppDatabase.journal_entry

HistoryScreen ─────────────── FocusSessionProvider
SettingsScreen
└─ DataTransferService ─────── AppDatabase + SharedPreferences
```

`Provider` 负责内存状态和页面刷新，`AppDatabase` 负责 SQLite 持久化；当前没有服务端、账号或云同步流程。

## 1. Todo 流程

```text
添加任务
→ 保存
→ 首页展示
→ 完成 / 取消完成
→ 删除
→ 开始专注
```

### 1.1 添加和保存

1. 首页按当前选中日期展示任务，点击添加后打开 `_AddTaskDialog`。
2. 用户提交后由 `TaskProvider.addTask()` 处理：
   - `title` 去除首尾空格；当前添加任务对话框会把空标题替换为“默认任务”，如果其他调用方直接向 Provider 传入空标题，则由 `addTask()` 忽略、不写入数据库。
   - `note` 去除首尾空格，空备注保存为 `NULL`。
   - `durationSeconds` 来自任务编辑器/添加对话框；添加任务对话框初始值为 25 分钟，而 `TaskProvider.addTask()` 未传入该参数时的代码默认值为 15 分钟。
   - `planDate` 归一化为本地日期当天零点。
   - 当前日期已有任务的 `sort_order` 整体后移，新任务使用顺序 `0`。
3. 非内存模式下调用 `AppDatabase.insertTask()` 写入 `task` 表，拿到自增 `id` 后加入 Provider 内存列表。
4. `TaskProvider` 通知监听页面，首页重新按 `plan_date`、`sort_order`、完成状态和创建时间展示。

任务的主要初始状态为：

```text
completed = false
completed_at = NULL
created_at = 当前时间
plan_date = 当前选中日期的当天零点
```

### 1.2 首页展示和编辑

- `TaskProvider.loadTasks()` 从 SQLite 读取全部任务。
- 首页通过 `tasksForDate(selectedDate)` 只展示当前日期的任务。
- 任务详情页可以修改标题、备注和专注时长，保存时调用 `updateTask()`。
- 拖动排序会更新同一日期内任务的 `sort_order`。

### 1.3 完成 / 取消完成

点击任务完成按钮后调用 `toggleTask()`：

```text
未完成 → completed = 1，completed_at = 当前时间
已完成 → completed = 0，completed_at = NULL
```

更新先写入 `task` 表，再替换 Provider 内存中的任务并刷新首页。已完成任务在首页不提供开始专注入口。

### 1.4 删除

1. 首页先弹出确认框。
2. 用户确认后调用 `TaskProvider.deleteTask()`。
3. `AppDatabase.deleteTask()` 只删除 `task` 表对应行。
4. 当前没有外键和级联删除，因此关联的 `focus_session` 历史记录不会被删除。

### 1.5 开始专注

未完成任务点击开始按钮后，将任务和 `task.durationSeconds` 传给 `FocusProvider` / `FocusScreen`。任务本身不会因为开始专注而改变 `completed` 状态；专注记录要到后续填写并保存本轮记录时才写入数据库。

## 2. 专注流程

```text
选择任务
→ 开始番茄钟
→ 倒计时
→ 暂停 / 继续
→ 正常结束或提前结束
→ 填写本轮做了什么
→ 保存 FocusSession
→ 历史记录可见
```

### 2.1 选择任务和开始

- 首页只允许未完成任务进入专注页。
- `TodayScreen` 持有当前活动的 `FocusProvider`，从专注页返回后仍可继续运行或暂停的本轮。
- `FocusScreen` 创建后，如果 Provider 仍是 `idle`，会自动调用 `start()`。
- `start()` 设置：
  - `startedAt = 当前时间`
  - `endsAt = startedAt + plannedDurationSeconds`
  - `status = running`
  - `remainingSeconds = 根据 endsAt 重新计算`
- 同时启动每秒一次的 UI ticker，并通过 `NotificationService` 预约结束提醒。

### 2.2 倒计时和显示

倒计时的真实时间来源是 `endsAt - 当前时间`，不是简单地每秒减一。`Timer.periodic` 只负责触发 UI 刷新；点击圆环可以切换剩余时间 / 已经过时间的显示方式，不改变实际计时。

### 2.3 暂停和继续

- 暂停只允许从 `running` 进入：先刷新一次剩余时间，再保存 `pausedRemainingSeconds`，清空 `endsAt`，停止 ticker，取消结束通知，进入 `paused`。
- 继续只允许从 `paused` 进入：以当前时间加上保存的剩余秒数重新计算 `endsAt`，恢复 ticker，重新预约通知，回到 `running`。

暂停不会写入 `FocusSession`，也不会改变任务完成状态。

### 2.4 正常结束和提前结束

#### 正常结束

当 `_refreshFromClock()` 发现 `endsAt` 已到：

```text
remainingSeconds = 0
endedAt = 当前时间
status = finished
停止 ticker
```

对于 `FocusMode.focus`，`FocusScreen` 自动打开 `FocusNoteScreen`。结束通知由本地通知系统触发；页面上仍提供“停止提醒”操作。

#### 提前结束

用户点击“结束专注”并确认后调用 `cancel()`：

```text
endedAt = 当前时间
status = cancelled
停止 ticker
取消结束通知
```

随后同样进入 `FocusNoteScreen`，但保存的 `FocusSession.status` 会是 `CANCELLED`，历史详情显示为“提前结束”。提前结束不会自动把任务标记为完成。

### 2.5 填写并保存本轮记录

`FocusNoteScreen` 在数据库写入前允许用户：

- 修改本轮记录中展示的任务标题；
- 填写“这段时间做了什么”；
- 留空笔记，此时 `focus_session.note` 保存为 `NULL`。

点击保存后创建 `FocusSession`：

| 来源                         | `FocusSession` 字段                             |
| ---------------------------- | ------------------------------------------------- |
| 原任务`id`                 | `task_id`                                       |
| 保存时的任务标题             | `task_title_snapshot`                           |
| Provider 记录                | `started_at`、`ended_at`                      |
| 计划时长                     | `planned_duration_seconds`                      |
| 实际时长                     | `actual_duration_seconds = endedAt - startedAt` |
| 文本框                       | `note`                                          |
| `finished` / `cancelled` | `COMPLETED` / `CANCELLED`                     |
| 保存时刻                     | `created_at`                                    |

`FocusSessionProvider.saveSession()` 调用 `AppDatabase.insertFocusSession()` 写入 `focus_session`，然后更新内存列表。

保存成功后：

- 正常完成：更新任务标题（如果用户在记录页修改了标题），然后进入 `FocusMode.rest` 的休息计时页；不会再次填写 FocusSession 笔记。
- 提前结束：更新任务标题后回到历史记录页。

因此，正常完成的 FocusSession 在进入休息页后已经持久化；历史页何时打开不影响记录是否保存。

### 2.6 休息流程

项目已经有休息模式，使用同一个 `FocusProvider` 状态枚举，但 `mode` 为 `FocusMode.rest`：

```text
正常专注记录保存
→ 新建休息模式计时器
→ 休息倒计时
→ 自然结束或跳过休息
→ 页面显示“开始专注”
```

休息不打开 `FocusNoteScreen`，也不会生成 `FocusSession`。用户可以暂停 / 继续休息，也可以从运行中或暂停状态跳过休息；休息结束后需要手动点击“开始专注”进入下一轮。

## 3. 日记流程

```text
今朝
→ 日记
→ 每日一问
→ 回答问题
→ 填写今日日记
→ 保存 / 修改
```

### 3.1 日期和页面

- 首页使用两个同步的日期分页：任务页和日记页。
- 底部导航切换到“日记”后，仍使用当前选中的日期。
- 左右滑动或日期选择器会同步两个分页；恢复到前台时，如果用户原本查看的是今天，会更新到新的本地日期。
- 页面默认问题由 `QuestionResolver.resolveDefaultQuestion()` 解析：生日 → 特殊日期 → 普通每日一问；已有 `daily_question` 仍由 `resolveQuestion()` 优先返回。随机问题池由 `QuestionRepository` 按需加载并缓存，不参与默认解析。

### 3.2 加载、保存和修改

1. 日记页按 `JournalEntry.dateKey(date)` 加载 `journal_entry` 和对应 `daily_question`。
2. 已有 `daily_question` 直接展示其 `question_text`；没有实例时只解析并展示默认问题，不立即写库。
3. 用户修改问题或保存回答 / 日记时，`QuestionService` 才创建或更新 `daily_question`，保留 `original_question_text`。
4. 保存时 `JournalProvider.saveJournal()` 先取得 `daily_question.id`，再调用 `AppDatabase.saveJournal()` 写入 `question_id`、回答和正文。
5. `entry_date` 的 `UNIQUE` 约束和按日期 upsert 逻辑共同保证每天最多一条 `JournalEntry`。

用户点击“换一个”时，`QuestionService` 从只读随机问题池中选择一条，排除当前题和最近 20 条随机题，并立即更新当天同一条 `daily_question`：`source_type = RANDOM`、`source_key = random:Rxxxx`、`is_modified = 1`。`original_question_text` 和 `created_at` 不变。手动编辑标为 `CUSTOM`；恢复默认重新解析 `DAILY` / `SPECIAL` / `BIRTHDAY` 来源，并恢复 `original_question_text`。

当前日记页实际保存的内容是：

- `entry_date`
- `question_id`
- `question_answer`
- `content`
- `created_at`
- `updated_at`

`question_text` 仍保留用于旧版本数据和备份兼容，但新写入不再依赖它作为正式问题来源。

## 4. 记录页

```text
FocusSession
→ 周统计
→ 月热力图
→ 年热力图
```

### 4.1 数据来源和筛选

- `FocusSessionProvider` 启动时从 `focus_session` 加载全部记录。
- 周 / 月 / 年视图均按 `startedAt.toLocal()` 归入本地日期和本地时间段。
- 统计时累加 `actualDurationSeconds`；当前实现不排除 `CANCELLED` 记录，取消的专注也会进入次数和时长统计。
- 记录列表按开始时间倒序展示，点开可查看详情并编辑 `note`。

### 4.2 周视图

- 默认进入周视图，当前锚点为今天。
- 周起始日由 `startOfFocusWeek()` 计算，展示连续 7 天。
- 每天显示专注时长柱状图；总时长、专注次数和日均时长从当周记录计算。
- 点击某天进入 `DayDetailScreen`，查看当天总时长、次数和记录列表。
- 左右按钮按 7 天移动。

### 4.3 月视图

- 展示指定月份的日历热力图。
- 每个日期格累加当天所有 `actualDurationSeconds`，颜色等级按该月最大日时长相对归一化。
- 显示当月总时长、次数和日均时长。
- 点击日期会在当前页面筛选该日记录列表；代码不会自动跳转到日详情页。
- 左右按钮按月移动。

### 4.4 年视图

- 展示 12 个月的年度热力概览。
- 每个月内部按日期分成 4 个时段桶：1–7 日、8–14 日、15–21 日、22 日至月底；各桶累加专注时长。
- 显示全年总时长、次数和月均时长。
- 点击某个月切换到该月的月视图。
- 年视图本身不显示下面的按日记录列表；左右按钮按年移动。

切换周 / 月 / 年时，页面会把时间锚点重置为当前日期；切换后再用左右按钮浏览对应粒度的前后周期。

## 5. 数据导入导出

### 5.1 导出

```text
设置
→ 导出数据
→ AppDatabase.exportData()
→ 拼接设置
→ JSON Backup
```

导出内容为格式化 JSON：

- `format: chrona_backup`
- `version: 1`
- `exported_at`
- `tasks`：对应 `task`
- `focus_sessions`：对应 `focus_session`
- `journal_entries`：对应 `journal_entry`
- `daily_questions`：对应 `daily_question`
- 可选 `settings.break_duration_seconds`、`birthday_month`、`birthday_day`：来自 `SharedPreferences`

系统文件选择器负责选择保存位置，文件扩展名为 `.json`，文件名包含导出日期。

### 5.2 导入

```text
选择 JSON
→ 解码和格式校验
→ 用户确认覆盖
→ Transaction 覆盖恢复
→ 恢复休息时长设置
```

实际行为如下：

1. 文件选择器只允许选择 JSON 文件。
2. `DataTransferService.pickBackup()` 解码 UTF-8 JSON，并校验 `format == chrona_backup`、`version == 1`。
3. 设置页弹出确认框，明确提示会覆盖当前任务、专注记录和日记。
4. `AppDatabase.importData()` 再次校验格式，读取四组数组，并在一个 SQLite transaction 中删除并恢复四张表；没有 `daily_questions` 的旧备份会从旧 `question_text` 重建问题实例。
5. 每行导入时会对缺省时间、ID、时长、布尔值和状态做当前代码中的兜底转换；日记日期必须符合 `YYYY-MM-DD`。
6. `settings.break_duration_seconds` 不在 SQLite transaction 中，而是在数据库恢复成功后写回 `SharedPreferences`。
7. 导入成功后页面提示重新打开 App，以刷新当前 Provider 已加载的数据。

## 6. 已实现、已设计和未实现的边界

### 已实现

- 本地任务 CRUD、完成状态、日期归属和排序。
- 基于 `endsAt` 的前台倒计时、暂停 / 继续、提前结束。
- 专注结束和休息结束的本地通知；Android 通知支持震动。
- FocusSession 写入、历史记录、周 / 月 / 年统计视图。
- 每日一条日记的加载、保存、修改。
- 任务、专注记录、日记和休息时长设置的 JSON 导入导出。

### 已设计但当前没有完整实现

- App 进程被系统杀死后的活动番茄钟恢复：当前没有把运行中的 `FocusProvider` 写入数据库或本地设置。
- 云同步、账号、多设备同步、项目 / 标签 / 子任务等扩展模型。
- 独立的统计数据表：统计由当前已加载的 `FocusSession` 在内存中即时计算。
- 取消的 FocusSession 是否应计入历史统计：当前周 / 月 / 年统计会计入。
- 正常完成后自动进入休息页、提前结束后直接进入历史页，是否符合最终产品流程。
- 年度热力图使用每月 4 个日期桶，而不是完整的月历网格，是否符合最终统计定义。
- 导入后要求重启 App 刷新 Provider，以及设置恢复不在 SQLite transaction 中，是否需要后续调整。
