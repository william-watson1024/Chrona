# 拾年 / CHRONA 数据备份与恢复

本文档记录当前已经实现的本地数据导入导出方案。运行时实现位于 `lib/services/data_transfer_service.dart` 和 `lib/database/app_database.dart`。

## 1. 目标和范围

CHRONA 当前是本地应用：

- 没有账号体系。
- 没有服务端数据源。
- 没有云同步。
- 业务数据保存在本地 SQLite `chrona.db`。
- 休息时长设置保存在 `SharedPreferences`。

备份用于：

```text
设备迁移
手动备份
数据恢复
```

当前恢复策略是“覆盖恢复”，不是合并恢复。

## 2. 导出

### 2.1 用户入口

```text
设置
→ 导出数据
→ 系统文件保存选择器
→ 保存 JSON 文件
```

导出过程中按钮会暂时禁用。用户取消文件保存时不生成文件，也不提示成功。

### 2.2 实际 JSON 格式

当前代码使用 snake_case 字段名，实际结构如下：

```json
{
  "format": "chrona_backup",
  "version": 1,
  "exported_at": "2026-09-29T00:00:00.000Z",
  "tasks": [],
  "focus_sessions": [],
  "daily_questions": [],
  "journal_entries": [],
  "settings": {
    "break_duration_seconds": 300,
    "birthday_month": 9,
    "birthday_day": 30
  }
}
```

字段规则：

| 字段 | 是否必有 | 内容 |
| --- | --- | --- |
| `format` | 是 | 固定为 `chrona_backup` |
| `version` | 是 | 当前为数字 `1` |
| `exported_at` | 是 | 当前 UTC 时间的 ISO 8601 字符串 |
| `tasks` | 是 | `task` 表行数据数组 |
| `focus_sessions` | 是 | `focus_session` 表行数据数组 |
| `daily_questions` | 否 | `daily_question` 表行数据数组；旧备份可缺少 |
| `journal_entries` | 是 | `journal_entry` 表行数据数组 |
| `settings` | 否 | 当前只包含休息时长设置 |

`tasks`、`focus_sessions`、`daily_questions` 和 `journal_entries` 由 SQLite 查询结果直接转换为 JSON 对象，字段与当前数据库列保持一致。导出顺序按各表 `id ASC`。

### 2.3 文件命名和编码

- 文件名：`chrona_backup_YYYYMMDD.json`。
- 日期使用导出设备的当前本地日期。
- 内容使用 UTF-8 编码。
- JSON 使用缩进格式，便于人工查看和排查。
- 文件选择器限制扩展名为 `.json`。

### 2.4 导出内容

数据库部分包括：

- `task`：任务、备注、完成状态、创建时间、完成时间、计划日期、排序和专注时长。
- `focus_session`：任务 ID、标题快照、开始 / 结束时间、计划 / 实际时长、笔记和状态。
- `journal_entry`：日期、每日一问、问题回答、日记正文和创建 / 更新时间。

设置部分导出 `break_duration_seconds` 和已设置时的 `birthday_month` / `birthday_day`。若用户从未保存过这些设置，导出的 JSON 可以没有对应字段或没有 `settings` 字段。

### 2.5 为什么使用 JSON 而不是直接导出 SQLite 文件

当前实现没有暴露原始 SQLite 文件路径，而是导出表行数据 JSON。这个方案直接支持：

- 通过 `format` 和 `version` 判断备份类型；
- 在导入时对字段做类型、空值和日期兜底；
- 不依赖设备上的 SQLite 文件路径；
- 把数据库数据和 `SharedPreferences` 设置放进同一个用户可保存的备份文件。

因此，JSON 是当前备份协议，不是 SQLite 文件的压缩副本。

## 3. 导入流程

```text
选择 JSON
→ UTF-8 解码
→ 校验 format / version
→ 用户确认覆盖
→ 校验数组和行数据
→ SQLite Transaction
→ 覆盖当前四张表
→ 恢复休息时长设置
→ 提示重新打开 App
```

### 3.1 选择和初步校验

1. 设置页打开系统文件选择器，只允许选择 JSON 文件，并要求读取文件字节。
2. 用户取消选择时，流程结束，不修改任何数据。
3. 服务使用 UTF-8 解码并解析 JSON。
4. 文件必须是 Map，并且满足：
   - `format == chrona_backup`
   - `version == 1`
5. 初步校验失败时抛出 `FormatException`，设置页提示“备份文件格式无效”。

### 3.2 用户确认

通过文件格式初步校验后，设置页显示确认框，明确说明导入会覆盖当前的任务、专注记录和日记。用户选择取消时，不执行数据库写入。

当前实现先校验备份信封的 `format / version`，更细的数组、行字段和日期校验在用户确认后进入 `AppDatabase.importData()` 时继续执行。

## 4. 导入策略：覆盖恢复

当前只支持：

```text
覆盖当前数据
```

不支持：

```text
数据合并
```

确认导入后，`AppDatabase.importData()` 在一个 SQLite transaction 中按以下顺序执行：

1. 删除 `journal_entry` 全部数据。
2. 删除 `focus_session` 全部数据。
3. 删除 `task` 全部数据。
4. 按备份内容重新插入 `task`。
5. 重新插入 `focus_session`。
6. 重新插入 `journal_entry`。

当前没有合并键、冲突解决、重复数据预览或逐条选择逻辑。没有 `daily_questions` 的旧备份会从非空 `journal_entry.question_text` 重建 `CUSTOM / legacy` 问题实例。

## 5. 数据一致性

### 5.1 SQLite Transaction 和失败回滚

- 四张业务表的删除和插入都在同一个 SQLite transaction 中。
- 事务内任一步骤抛出异常时，SQLite 回滚本次事务，避免只恢复一部分表。
- 日记日期不符合 `YYYY-MM-DD` 时会抛出格式异常。
- 备份字段不是数组时会被视为无效备份。
- 文件无法读取、无法解码、JSON 结构无效或导入失败时，设置页显示失败提示。

当前 `_backupRows()` 只收集 Map 类型的行；数组中的非 Map 项会被忽略。行内缺少部分可恢复字段时，导入函数会使用当前代码中的默认值或由时间字段计算兜底值。

### 5.2 Task / FocusSession ID 关联

- 如果备份行中的 `id` 是可读取的整数，导入时会保留该 ID。
- `focus_session.task_id` 也会按备份值保留，不会重新映射。
- 因此，来源备份中的任务 ID 和专注记录 `task_id` 一致时，导入后逻辑关联保持不变。
- 当前数据库没有外键约束，导入过程不会验证 `task_id` 是否确实存在于 `task`；不一致的备份可能保留孤立的逻辑关联。

### 5.3 Settings 恢复

`settings.break_duration_seconds` 不属于 SQLite transaction：

1. 四张数据库表恢复成功后，`DataTransferService` 才写回 `SharedPreferences`。
2. 值必须是数字且大于 0 才会恢复。
3. 备份没有 `settings` 或没有有效休息时长时，当前设备原有设置保持不变。
4. 数据库恢复和设置恢复不是一个原子操作；设置写入失败不会回滚已经成功的数据库事务。

设置页在导入成功后还会更新当前的 `FocusSettingsProvider`，但任务、专注记录和日记 Provider 已经加载的列表不会自动重读。界面会提示用户重新打开 App 以刷新数据。

## 6. 无效文件和错误行为

| 情况 | 当前行为 |
| --- | --- |
| 用户取消选文件 | 不修改数据 |
| 文件不是有效 JSON | 导入失败提示 |
| 顶层不是对象 | 格式无效 |
| `format` 不匹配 | 格式无效 |
| `version` 不是 `1` | 格式无效 |
| `tasks` / `focus_sessions` / `journal_entries` 不是数组 | 导入失败并回滚数据库事务 |
| 日记日期不是 `YYYY-MM-DD` | 导入失败并回滚数据库事务 |
| 单行缺少可兜底字段 | 使用当前导入函数的默认值 |
| 数据库插入失败 | SQLite transaction 回滚 |
| 设置写入失败 | 数据库不会回滚；当前设置恢复失败 |

导入和导出按钮在操作期间禁用，避免同一页面同时触发多个文件操作。

## 7. 备份版本

当前协议固定为：

```text
format = chrona_backup
version = 1
```

当前没有复杂的备份迁移框架。未来升级备份格式时，应提升 `version` 并在导入入口按版本分支处理；版本 1 的字段含义和覆盖逻辑保持稳定，直到明确引入新的兼容策略。
