# 拾年 / CHRONA 数据模型与表结构

本文档是产品级数据模型入口。字段明细、SQL 快照和迁移记录复用现有 [`database-schema/`](./database-schema/) 文档，不在此重新设计一套数据库。

运行时数据库定义以 [`lib/database/app_database.dart`](../lib/database/app_database.dart) 为准。

当前数据库：

- 文件名：`chrona.db`
- 数据库：SQLite，通过 `sqflite` 使用
- 当前 schema version：`7`
- 当前业务表：`task`、`focus_session`、`journal_entry`

## 1. 领域模型

```text
Task
= 用户准备做什么

FocusSession
= 用户实际花了一段时间做了什么

JournalEntry
= 某一天的问题、回答和日记
```

业务关系：

```text
Task 1 ── 0..N FocusSession
```

`focus_session.task_id` 是可为空的逻辑关联字段，当前数据库没有声明 SQLite 外键。`FocusSession` 同时保存 `task_title_snapshot`，因此任务删除后仍可以展示历史记录中的任务名称。

`JournalEntry` 不依赖任务或专注记录，通过 `entry_date` 保证每天最多一条。

## 2. Task（`task`）

### 用途

保存用户准备完成的任务，以及任务的完成状态、计划日期、排序和默认专注时长。

### 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `INTEGER` | 主键，自增 |
| `title` | `TEXT NOT NULL` | 任务标题 |
| `note` | `TEXT` | 任务备注，可为空 |
| `completed` | `INTEGER` | 完成状态，`0/1` |
| `created_at` | `INTEGER NOT NULL` | 创建时间 |
| `completed_at` | `INTEGER` | 完成时间，可为空 |
| `duration_seconds` | `INTEGER NOT NULL` | 任务关联的专注时长，单位秒 |
| `plan_date` | `INTEGER NOT NULL` | 任务所属日期，按本地日期零点保存 |
| `sort_order` | `INTEGER NOT NULL` | 同日任务排序值 |

### 约束与业务规则

- `id` 是数据库主键；没有其他唯一约束。
- `title` 不允许为空。
- `completed` 在 SQLite 中以 `INTEGER` 的 `0/1` 表示。
- 完成任务时写入 `completed_at`；取消完成时清除完成时间。
- 新增或移动任务时会维护同一天任务的 `sort_order`。
- 删除任务只删除 `task` 行，不级联删除 `FocusSession`。
- 任务标题、备注和专注时长可以在任务编辑流程中更新。

完整字段定义见 [`database-schema/tables/task.md`](./database-schema/tables/task.md)，SQL 快照见 [`database-schema/schema.sql`](./database-schema/schema.sql)。

## 3. FocusSession（`focus_session`）

### 用途

保存一轮番茄钟实际产生的专注记录，用于历史列表、周统计、月热力图和年热力图。

### 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `INTEGER` | 主键，自增 |
| `task_id` | `INTEGER` | 逻辑关联的任务 ID，可为空 |
| `task_title_snapshot` | `TEXT NOT NULL` | 保存时的任务标题快照 |
| `started_at` | `INTEGER NOT NULL` | 开始时间 |
| `ended_at` | `INTEGER NOT NULL` | 结束时间 |
| `planned_duration_seconds` | `INTEGER NOT NULL` | 计划专注时长，单位秒 |
| `actual_duration_seconds` | `INTEGER NOT NULL` | 实际专注时长，单位秒 |
| `note` | `TEXT` | 本轮完成内容，可为空 |
| `status` | `TEXT NOT NULL` | 当前为 `COMPLETED` 或 `CANCELLED` |
| `created_at` | `INTEGER NOT NULL` | 记录创建时间 |

### 约束与业务规则

- `id` 是数据库主键；没有其他唯一约束。
- `task_id` 可为空，数据库没有声明外键。
- 番茄钟运行或暂停过程中不会写入数据库；用户在本轮记录页保存后才创建 `FocusSession`。
- `task_title_snapshot` 保存本轮记录使用的任务标题。任务删除后，历史记录仍依靠该快照展示任务信息。
- `actual_duration_seconds` 根据本轮开始和结束时间计算；按当前实现，暂停期间也会计入实际时长。
- 正常结束保存为 `COMPLETED`，用户提前结束保存为 `CANCELLED`；两者都属于历史记录和统计数据来源。

完整字段定义见 [`database-schema/tables/focus_session.md`](./database-schema/tables/focus_session.md)。

## 4. JournalEntry（`journal_entry`）

### 用途

保存某一天的每日一问、回答和今日日记内容。

### 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `INTEGER` | 主键，自增 |
| `entry_date` | `TEXT NOT NULL UNIQUE` | 业务日期，格式 `YYYY-MM-DD` |
| `question_id` | `INTEGER` | 问题 ID，可为空 |
| `question_text` | `TEXT` | 当天展示的问题，可为空 |
| `question_answer` | `TEXT` | 对问题的回答，可为空 |
| `content` | `TEXT` | 今日日记正文，可为空 |
| `created_at` | `INTEGER NOT NULL` | 创建时间 |
| `updated_at` | `INTEGER NOT NULL` | 最后更新时间 |

### 约束与业务规则

- `id` 是数据库主键。
- `entry_date` 是业务唯一键，不是数据库主键；同一天只能存在一条记录。
- 保存当天日记时使用新增或更新逻辑，不应为同一天创建重复记录。
- 更新记录时保留 `created_at`，刷新 `updated_at`。
- 当前页面允许修改当天问题文本；当前保存流程实际依赖 `question_text`，`question_id` 可以为空。

完整字段定义见 [`database-schema/tables/journal_entry.md`](./database-schema/tables/journal_entry.md)。

## 5. 存储约定

| 数据 | 当前存储方式 |
| --- | --- |
| 主键和 ID | SQLite `INTEGER` |
| 时间戳 | `INTEGER`，Unix epoch 毫秒 |
| 业务日期 | `TEXT`，格式 `YYYY-MM-DD` |
| 专注时长 | `INTEGER`，单位秒 |
| Boolean | SQLite `INTEGER`，`0` 表示 false，`1` 表示 true |
| 专注状态 | `TEXT`，当前值为 `COMPLETED` / `CANCELLED` |

页面展示格式由现有格式化工具统一处理；不要在新页面中各自定义时间、日期或时长格式。

## 6. Schema version 与 migration

当前版本为 `7`，迁移顺序如下：

| 版本 | 变化 |
| --- | --- |
| `1` | 创建基础 `task` 表 |
| `2` | 为 `task` 增加 `duration_seconds`，默认值为 900 秒 |
| `3` | 创建 `focus_session` 表 |
| `4` | 为 `task` 增加 `plan_date`，并为已有任务回填本地日期 |
| `5` | 为 `task` 增加 `sort_order`，并为已有任务回填排序值 |
| `6` | 修复已有数据中的空值 |
| `7` | 创建 `journal_entry` 表 |

数据库结构变更必须提升 schema version，并在 `onUpgrade` 中提供迁移；不能通过删除数据库或直接丢弃用户数据完成升级。详细记录见 [`database-schema/migration-history.md`](./database-schema/migration-history.md)。

## 7. 其他持久化数据

当前没有第四张业务表。设置中的休息时长保存在 `SharedPreferences`，键为 `break_duration_seconds`。数据导出时会将该设置放入备份 JSON 的 `settings` 对象，导入时再恢复。

备份和恢复行为见 [`007.数据备份与恢复.md`](./007.数据备份与恢复.md)。

## 8. 当前待确认项

- 专注时长默认值在不同代码路径中不完全一致：数据库默认值和 `TaskProvider.addTask` 默认值为 15 分钟；新增任务界面的初始值、`Task` 模型默认值以及部分导入/空值修复回退值为 25 分钟。新增功能不能据此擅自选择一个“统一值”；如需统一，应作为单独任务同时核对 UI、Provider、Model、迁移和备份逻辑。
- `question_id` 已存在于表结构，但当前页面主要保存 `question_text`，其具体问题库语义目前没有进一步实现。
