
# 拾年 / CHRONA 核心功能

请在现有 Flutter 项目中实现第一版核心业务链路。

技术栈保持：

- Flutter + Dart
- Provider
- SQLite + sqflite
- shared_preferences
- flutter_local_notifications
- Android 优先

不要引入后端、登录、云同步或复杂架构。

## 1. 添加任务

首页支持新增任务。

任务至少包含：

```text
id
title
completed
createdAt
```

任务保存到 SQLite，App 重启后仍然存在。

支持：

- 新增
- 完成 / 取消完成
- 删除
- 点击任务右侧 ▶ 开始专注

---

## 2. 开始专注

点击任务的 ▶ 后进入专注页面。

默认专注时间：

```text
25:00
```

暂时允许设置为较短时间，方便开发测试。

页面核心展示：

```text
阅读 Orca 论文

24:37

专注中

[暂停]
[结束]
```

倒计时必须精确到秒。

不要通过简单的：

```dart
remainingSeconds--
```

作为真实时间来源。

开始时记录：

```text
startedAt
endsAt
```

剩余时间始终通过：

```text
endsAt - DateTime.now()
```

计算。

`Timer.periodic` 只负责刷新 UI。

要求：

- 前台计时正确
- 切后台后重新打开时间正确
- 锁屏后重新打开时间正确
- 暂停 / 继续正确
- 不因为 Flutter Timer 被暂停导致计时漂移

---

## 3. 时间结束提醒

倒计时到 `00:00` 后：

1. 停止倒计时
2. 手机开始震动提醒
3. 不播放声音
4. 发出本地通知
5. 进入“本轮完成”状态

使用 `flutter_local_notifications` 处理后台到点提醒。

通知 Channel：

```text
声音：关闭
震动：开启
```

需要正确处理 Android 通知权限以及精确定时相关能力。

---

## 4. 停止震动

用户必须能够主动停止提醒。

可靠方式必须提供：

```text
通知操作：[停止震动]
```

App 在前台时，也提供：

```text
[停止震动]
```

如果 Flutter / Android 在当前运行状态下能够可靠检测硬件音量键，则：

```text
按音量+ 或音量-
→ 立即停止震动
```

但注意：

- 不使用 AccessibilityService
- 不申请与功能明显无关的高权限
- 不为了监听音量键破坏系统正常音量行为
- Android 后台或锁屏无法可靠监听时，使用通知按钮兜底
- 不要伪造“全局音量键一定可用”的实现

---

## 5. 本轮专注记录

停止提醒后，显示：

```text
本轮专注完成

阅读 Orca 论文
20:00 - 20:25
25 min

这段时间做了什么？

[_____________________]
[_____________________]

[保存]
```

用户填写本轮实际完成内容，例如：

```text
看完 Introduction 和 Section 2，
整理了 Continuous Batching 笔记。
```

保存到 SQLite。

建立 `focus_session`：

```text
id
taskId
startedAt
endedAt
durationSeconds
note
status
```

---

## 6. 历史记录

保存后可以在「记录」页面看到：

```text
今天

20:00 - 20:25
阅读 Orca 论文
看完 Introduction 和 Section 2

18:30 - 18:55
写 RagForge
完成 DocumentService 设计
```

按照时间倒序展示即可。

暂时不做图表和复杂统计。

---

## 7. 状态流转

核心状态保持清晰：

```text
IDLE
 ↓
RUNNING
 ↓
PAUSED
 ↓
RUNNING
 ↓
FINISHED
 ↓
WAITING_FOR_NOTE
 ↓
SAVED
```

用户主动提前结束时也要正确保存实际结束时间，但不要自动视为完整番茄钟。

---

## 8. 数据模型

第一版只需要：

```text
Task
FocusSession
```

不要增加：

- Project
- Tag
- Habit
- SubTask
- Account
- CloudSync

---

## 9. 验收标准

完成后我需要能够实际验证：

```text
1. 新建一个 Todo
2. 点击 ▶ 开始专注
3. 秒级倒计时正常
4. 锁屏一段时间再回来，剩余时间仍正确
5. 时间到手机只震动、不响铃
6. 可以停止震动
7. 填写“这一轮做了什么”
8. 保存后历史页能看到记录
9. 杀掉并重新打开 App，Task 和历史记录仍存在
```

为方便开发，请允许临时把番茄钟设置成：

```text
10 秒 / 30 秒 / 1 分钟
```

用于测试完整流程。

## 10. 开发要求

优先级：

```text
计时可靠性
> 通知与震动可靠性
> 数据正确性
> UI 美观
```

保持代码简单。

不要擅自：

- 引入 Clean Architecture
- 引入 Riverpod / Bloc / GetX
- 创建大量 Repository Interface / UseCase / Mapper
- 重构与本功能无关的代码
- 实现后续统计、习惯、云同步等功能

完成后只告诉我：

1. 修改了哪些文件
2. 核心计时方案
3. 通知和震动如何实现
4. SQLite 表结构
5. 如何逐项验证上述 9 条验收标准
