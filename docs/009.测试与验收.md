# 拾年 / CHRONA 测试与验收

本文档是当前项目的人工验收清单，不是测试框架教程。除特别注明外，测试以真实 SQLite、真实 Provider 和真实本地通知配置运行。

## 0. 测试准备

- 使用可快速验证的专注时长，例如 10 秒、30 秒或 1 分钟。
- 首次运行时完成通知权限请求，并确认设备允许通知和震动。
- 测试前记下已有任务、FocusSession、日记和休息时长，避免覆盖恢复测试误伤数据。
- 需要验证持久化时，关闭并重新打开 App，而不是只返回上一页。
- 需要验证导入回滚时，准备一份能通过 `format / version` 初步校验、但包含非法行数据的 JSON。

## 1. Todo

- [ ] 可以新增任务，任务出现在当前选中日期。
- [ ] 新任务标题和备注的首尾空格按当前实现处理。
- [ ] 添加任务对话框空标题时，当前实现保存为“默认任务”；如果产品要求空标题不能保存，应作为单独需求验收，不把两种行为混为一谈。
- [ ] 可以修改任务标题、备注和专注时长。
- [ ] 可以完成任务，任务显示完成样式并记录 `completed_at`。
- [ ] 可以取消完成，完成样式消失并清空 `completed_at`。
- [ ] 可以删除任务；删除前显示确认框。
- [ ] 拖动任务后，同一日期内的排序保持正确。
- [ ] 已完成任务不能从首页开始专注。
- [ ] App 重启后任务、完成状态、计划日期和排序仍存在。
- [ ] 点击未完成任务的开始按钮，可以带着正确任务和计划时长进入专注页。

## 2. 番茄钟

- [ ] 开始后按秒显示倒计时，计时依据真实结束时间而不是单纯递减次数。
- [ ] 点击计时区域可以切换剩余时间 / 已经过时间显示，实际计时不被改变。
- [ ] 暂停后 ticker 停止，剩余时间保持不继续减少。
- [ ] 暂停后继续，按暂停时的剩余时间重新计算结束时间。
- [ ] 运行中确认“结束专注”后进入提前结束流程。
- [ ] 暂停中确认结束同样进入提前结束流程。
- [ ] 正常倒计时结束后显示“已完成”，并进入本轮记录页。
- [ ] 计时页返回首页后，再次打开同一运行中或暂停中的任务可以继续原本的计时。
- [ ] 切后台后返回，剩余时间按真实时间重新计算。
- [ ] 锁屏后解锁，剩余时间按真实时间重新计算。
- [ ] App 回到前台且 `endsAt` 已经过期时，状态切换为已完成并进入记录流程。
- [ ] App 进程被系统杀死后，记录当前行为：代码不会从数据库恢复活动中的 `FocusProvider`，不应把它误判为已支持恢复。

## 3. 提醒、通知和震动

- [ ] 首次运行能够请求通知权限。
- [ ] 专注结束时能够出现本地通知并触发震动。
- [ ] 专注通知默认不播放声音。
- [ ] 休息结束时能够出现通知、播放系统默认声音并触发震动。
- [ ] 暂停后原结束通知被取消。
- [ ] 继续后按新的 `endsAt` 重新预约通知。
- [ ] 提前结束后不会继续收到原专注结束通知。
- [ ] 跳过休息后不会继续收到原休息结束通知。
- [ ] 通知中的“停止提醒”操作可以取消提醒；计时页和本轮记录页的“停止提醒”也可以执行取消。
- [ ] 在深度省电场景下允许系统存在少量通知延迟；当前使用的是 `inexactAllowWhileIdle`，不是 exact alarm。

## 4. FocusSession

- [ ] 正常完成专注、填写笔记并保存后，生成一条 `COMPLETED` FocusSession。
- [ ] 提前结束、填写笔记并保存后，生成一条 `CANCELLED` FocusSession。
- [ ] 可以填写“这段时间做了什么”，空笔记按当前实现保存为 `NULL`。
- [ ] 本轮记录页可以修改任务标题，保存后任务标题和历史标题快照符合当前行为。
- [ ] 保存过程中不能重复创建多条相同记录。
- [ ] 正常完成保存后进入休息计时；提前结束保存后进入历史记录页。
- [ ] 保存成功后，打开历史页能看到新记录。
- [ ] App 重启后 FocusSession 仍存在。
- [ ] 删除原任务后，历史记录仍能通过 `task_title_snapshot` 正确展示。
- [ ] 历史详情页可以修改 FocusSession 笔记并保存。
- [ ] 验证实际时长时注意当前实现使用 `endedAt - startedAt`，暂停期间也会计入实际时长。

## 7. 数据导出

- [ ] 设置页可以生成 JSON 备份文件。
- [ ] 文件名符合 `chrona_backup_YYYYMMDD.json`。
- [ ] JSON 包含 `format = chrona_backup`。
- [ ] JSON 包含 `version = 1`。
- [ ] JSON 包含 `tasks` 数组。
- [ ] JSON 包含 `focus_sessions` 数组。
- [ ] JSON 包含 `journal_entries` 数组。
- [ ] 已保存过休息时长设置时，JSON 包含 `settings.break_duration_seconds`。
- [ ] 未保存过休息时长设置时，允许 JSON 不包含 `settings`。
- [ ] 导出的 `exported_at` 是 UTC ISO 8601 时间字符串。
- [ ] 导出取消时不应误提示“导出成功”。

## 8. 数据导入

- [ ] 可以选择合法的 CHRONA JSON 备份。
- [ ] 非法 JSON 会被拒绝并显示失败提示。
- [ ] `format` 不正确的文件会被拒绝。
- [ ] 不支持的 `version` 会被拒绝。
- [ ] 初步校验通过后，导入前显示覆盖确认框。
- [ ] 取消确认不会修改当前数据。
- [ ] 合法导入会覆盖当前任务、FocusSession 和 JournalEntry，而不是合并。
- [ ] 导入失败时，四张 SQLite 表保持导入前状态，验证 transaction 回滚。
- [ ] 合法备份中的 Task ID 和 `focus_session.task_id` 关联保持不变。
- [ ] 日记日期非法时导入失败并回滚。
- [ ] `settings.break_duration_seconds` 能恢复到 SharedPreferences。
- [ ] 没有 `settings` 时，当前设备原有休息时长保持不变。
- [ ] 导入成功后按页面提示重新打开 App，确认任务、记录、日记和设置都正确刷新。
- [ ] 不把“导入后当前页面立即刷新”作为当前已支持行为；当前代码主要通过重启 App 刷新已加载 Provider。

## 9. 数据库和迁移回归

- [ ] 新安装可以创建数据库版本 8 的四张表。
- [ ] 旧版本升级按 `onUpgrade` 顺序执行，不丢失原有任务数据。
- [ ] `task.plan_date`、`task.sort_order` 和 `duration_seconds` 在升级后有正确值。
- [ ] `journal_entry.entry_date` 保持每日唯一。
- [ ] `focus_session.task_id` 按当前逻辑关联工作，不依赖未声明的外键。
- [ ] 数据库写入失败时，调用方能够显示失败状态，不把未保存数据误报为成功。

## 10. 回归范围

每次涉及以下任一项的改动后，至少重新验收：

```text
Todo
番茄钟
通知与震动
FocusSession
记录页
日记
数据导入导出
```

最低回归组合：

- 修改数据库或 Model：Todo、FocusSession、日记、导入导出、App 重启恢复。
- 修改计时器或通知：开始、暂停、继续、提前结束、正常结束、后台、锁屏、休息通知。
- 修改 Provider：对应业务写入、页面刷新、错误和重复操作保护。
- 修改备份格式：导出字段、版本校验、覆盖恢复、事务回滚、ID 关联和设置恢复。
- 修改公共 UI：今朝、专注、日记、记录、设置和底部导航的基本布局与交互。

## 11. 当前验收边界

以下不是本次验收失败，而是当前代码尚未提供的行为，测试时应明确区分：

- App 进程被杀死后不会自动恢复正在运行的 `FocusProvider`。
- Android 通知使用非精确定时，深度省电下可能有少量延迟。
- 导入时 SharedPreferences 设置不和 SQLite 表处于同一个原子事务。
- 导入成功后已加载的业务 Provider 不会自动全量重载，当前流程要求重新打开 App。
- 当前日期格式化函数输出 `M月D日·星期X`，不是中点两侧带空格的版本。
